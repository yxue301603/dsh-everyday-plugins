# 反馈与建议 / Feedback

八个插件的新问题和建议统一提交到[工具箱 Issues](https://github.com/yxue301603/dsh-everyday-plugins/issues)，包括之前从 `dsh-quick-prompts` 等独立仓库安装的版本。可以用中文或 English。独立仓库已有问题继续保留，不需要到这里重复发一份。

Use the [collection issue tracker](https://github.com/yxue301603/dsh-everyday-plugins/issues) for new feedback about any of the eight tools, including copies installed from older standalone repositories. Chinese and English are welcome. Existing standalone issues remain valid; do not duplicate them here.

## 选一个入口 / Choose a starting point

- [报告问题 / Report a bug](https://github.com/yxue301603/dsh-everyday-plugins/issues/new?template=bug_report.yml)：安装失败、界面错位、无法保存或行为不符合预期。
- [提出使用建议 / Suggest an improvement](https://github.com/yxue301603/dsh-everyday-plugins/issues/new?template=feature_request.yml)：告诉我们经常做什么，以及哪一步最费事。
- 文档错误也可用上述入口，或直接[提交 PR](../CONTRIBUTING.md)。没有 GitHub 账号时，不需要为反馈公开个人联系方式；可以先保存下面的简短记录，之后再提交。

Bug reports cover installation, layout, saving and unexpected behavior. Suggestions are most useful when they describe a recurring task and its friction. Documentation corrections can use either form or a [pull request](../CONTRIBUTING.md). No personal contact details are required.

提交前先搜索已有 Issues。[安装指南](INSTALLATION.md)已说明重复入口、Web/Desktop profile、GitHub 下载及本地数据来源隔离等常见情况；不必为了反馈先重装或清除数据。

Search existing issues first. The [installation guide](INSTALLATION.md) covers duplicate tools, Web/Desktop profiles, GitHub downloads and origin-local storage. You do not need to reinstall or clear data before reporting.

## 一个够用的问题记录 / A useful minimal report

```text
插件 / Tool:
DSH 版本 / DSH version:
插件版本 / Plugin version:
系统与客户端 / OS and Desktop/Web:
安装形式 / Collection, #path subdirectory, standalone repo, or local:
最少复现步骤 / Minimum reproduction steps:
预期结果 / Expected:
实际结果 / Actual:
```

找不到版本可填 `unknown`。界面问题可补充深浅主题和大致窗口宽度。简短错误、脱敏截图均为可选；不要求上传完整日志、配置或项目。

Use `unknown` if a version is unavailable. For layout problems, theme and approximate window width help. A short error or redacted screenshot is optional. Full logs, configuration and project uploads are not required.

## 保留最少信息 / Keep shared details minimal

请使用虚构消息和测试文件名复现。不要贴 API Key、token、凭据文件、个人会话正文或完整配置。截图前检查侧栏的项目名和会话标题；日志只节选相关错误，并隐藏账号、路径和链接中的私人信息。无法脱敏时，只描述现象即可。

Reproduce with synthetic messages and filenames. Do not post API keys, tokens, credential files, personal chat content or complete configuration. Check project names and chat titles in screenshots. Share only the relevant error excerpt and redact private account, path or URL details. A plain description is enough when material cannot be safely redacted.

维护者会在原 Issue 中沟通；无需提供邮箱或其他账号。反馈是为了改善使用体验，不要求 star、转发或加入群聊。

Follow-up stays in the issue; no email or other account is needed. Feedback does not require starring the repository, sharing it or joining a group.
