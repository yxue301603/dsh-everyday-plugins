# DSH 日常工具箱开发计划

## 目标

完成 8 个日常 DeepSeek Harness 原生插件，延续首个快捷指令插件的可用性、独立安装与双语文档要求。提供一个可整套安装的总仓库，以及 8 个可按需安装的独立 GitHub 来源。

开发以后台文件操作和隔离的测试实例为主，不使用用户正在工作的真实桌面完成自动化测试。集中验证后再发布和处理本地安装；不为测试重启用户正在使用的 DSH。

## 范围

正式清单由根目录 `catalog.mjs` 管理：

| 插件 | 本轮重点 |
| --- | --- |
| `dsh-quick-prompts` | 保留已有功能、存储键和独立仓库，纳入总包 |
| `dsh-conversation-outline` | 已加载提问检索、原生定位、手动加载更早历史、阅读位置 |
| `dsh-draft-history` | 会话隔离、停顿自动记录、清空保护、预览、安全插入与确认替换 |
| `dsh-answer-library` | 回答与摘录收藏、标签搜索、复制/插入、来源定位 |
| `dsh-turn-files` | 按轮次整理原生交付、改动清单和支持的成功文件写入 |
| `dsh-task-alerts` | 可靠区分实时结束与待确认、未读记录、用户主动开启系统通知 |
| `dsh-project-notes` | 工作区便笺、自动保存、待办、选中插入、Markdown 导出 |
| `dsh-selection-actions` | 当前消息选区、引用追问/翻译/解释、来源定位、不自动发送 |

兼容基线为 DSH **0.2.1-rc.2**，版本范围限定在 0.2.x；Web 与桌面环境分别核验。对未验证版本不作兼容承诺。

## 集中验收

### 可用性与界面

- 表单标签、输入内容、占位符、主按钮和禁用状态在深浅主题下都能辨认，避免白底白字。
- 输入框扩展遵循宿主宽度；模态框支持窄屏、键盘退出和合理焦点恢复。
- 插件并存时入口可区分；重复安装形式在文档中明确说明。
- 中文、英文界面没有影响操作的缺字、溢出或未翻译状态。

### 数据与原生接口

- 草稿插入使用官方接口和修订校验，不自动发送，不无提示替换文本、附件或引用。
- 会话及工作区隔离；选区、原文定位和阅读位置不跨会话串用。
- 存储失败可见，损坏记录不静默覆盖；便笺的未保存文本可复制或导出。
- 文件列表仅依据可解释的原生来源，不把终端输出中任意路径推断为成功写入；预览与目录定位保留宿主授权范围。
- 提醒不回放旧历史，不将未知结果当成功，不将已结束的阻断状态误报为当前待确认。
- 所有监听、定时器、通知及订阅随插件停用清理。

### 安装与发布

- 根包真正包含 8 个客户端，独立包携带各自构建产物，无需使用者编译。
- 本地数据键在独立版与总包之间保持一致，已有快捷指令资料可继续读取。
- 不把 Web profile 安装当作桌面安装；本地核验保持个人会话、凭据和正在运行任务不受干扰。
- 文档仅声明已经观察到的结果；未测能力和宿主限制单独记录。

## 中断与恢复

若执行额度不足，应停在源码已保存、构建或测试结果已记录、没有未完成真实安装的阶段。保留具体待办和可复跑命令，避免留下半更新的用户 DSH 配置或需要后台测试进程持续运行才能使用的状态。

未完成验证时不标记目标完成，也不将「源码形成」写成「全部测试通过」。发布与本地安装进度分别记录，便于从中断处继续。
